# Codex → Claude Code 고도화 인계 계약

## 책임 분리

```text
Codex: 분석과 고도화 계획
  ↓ _workspace/CODEX_PLAN.md
Claude Code: 계획 기반 구현과 테스트
  ↓ _workspace/CLAUDE_IMPLEMENTATION.md
사용자: 결과 검토 및 다음 지시
```

두 도구 모두 `.harness/`의 민원 업무 구조를 변경의 기준으로 사용한다. 핵심 성공 조건은 실제 앱에서 입력 → 처리 → 검증 → 출력 흐름과 Agent handoff가 드러나는 것이다.

## Codex 계획 산출물

Codex는 `_workspace/CODEX_PLAN.md`를 다음 형식으로 작성한다.

```markdown
# 고도화 계획

## 목표와 사용자 가치
## 현재 구조와 Gap
## 목표 업무 흐름
## 변경 대상 / 비대상
## 구현 작업

### 작업 1: 제목
- 담당 업무 Agent:
- 대상 파일과 심볼:
- 변경 내용:
- 입력/출력 계약:
- 상태 전이:
- 오류 처리:
- 테스트:
- 완료 조건:

## 작업 순서와 의존성
## 마이그레이션/호환성
## 위험과 완화책
## 전체 검증 명령
## 사용자 결정 필요 사항
```

계획은 “리팩터링한다” 같은 추상적 표현으로 끝내지 않고 Claude Code가 찾을 파일, 함수, 데이터 필드와 판정 기준을 명시한다.

## Claude Code 구현 산출물

Claude Code는 계획을 구현한 뒤 `_workspace/CLAUDE_IMPLEMENTATION.md`를 작성한다.

```markdown
# 구현 결과

## 구현 요약
## 계획 대비 변경 사항
## 변경 파일과 핵심 심볼
## 데이터 계약 및 상태 전이
## 실행한 테스트와 결과
## 실행하지 못한 테스트
## 안전성 검토 결과
## 남은 작업과 알려진 위험
```

## 공통 금지 사항

- Codex 계획 없이 Claude가 범위를 크게 확장하지 않는다.
- `PASS` 없는 민원 초안을 승인 출력하지 않는다.
- 근거가 없는 법령·조문을 생성하지 않는다.
- API 키와 실제 민원 개인정보를 산출물이나 커밋에 남기지 않는다.
- 루트 메인 구현과 참고 패키지 구현을 이유 없이 동시에 변경하지 않는다.
- 기존 사용자 변경을 덮어쓰지 않는다.

## 완료 판정

- Codex 계획이 파일·계약·테스트 수준으로 구체적이다.
- Claude 구현 기록이 계획 항목과 1:1로 대응한다.
- 입력 → 처리 → 검증 → 출력이 코드와 Pixel Runtime trace에서 확인된다.
- 자동 검증과 수동 검증 결과가 PASS/FAIL/NOT RUN으로 구분된다.
- 사람 검토 전환과 안전한 실패 경로가 동작한다.
